# demo/ — counterfactual demo contract (Phase 6)

The single most-watched artifact pair in the repo. The 2-minute
asciinema screencast runs against `known-bad-nda.pdf`; the
`expected-redline.docx` is the static reference for "this is
what the system should produce when the user approves all
five deviations."

## Files

| File | What it is |
|---|---|
| `known-bad-nda.pdf` | A 1-page mutual NDA with **5 hand-crafted deviations** from the Phase 2 playbook baselines. Generated by `scripts/build_demo_known_bad_nda.py` (reportlab, deterministic, idempotent). |
| `expected-redline.docx` | The expected output of running the system against `known-bad-nda.pdf` and approving all 5 deviations. Five `w:ins` / `w:del` tracked-changes pairs, one per deviation. Generated by `scripts/build_demo_expected_redline.py` (python-docx + raw lxml for the tracked changes). |
| `expected-deviations.yaml` | The Phase-2-eval-harness-shaped golden YAML listing the 5 expected deviations. Drives `evals/harness.py` so the demo's deviation count is verified, not assumed. |
| `README.md` | This file. |

## The 5 deviations

The deviations are calibrated to the 5 Phase 2 NDA-EN playbook
baselines (`playbook/baselines/nda-en/*.yaml`). Each one is
a real-world NDA pitfall a hiring manager or junior associate
would recognize from a 2-minute read-through.

| # | Clause | Severity | Category | What's wrong |
|---|---|---|---|---|
| c1 | Definition of Confidential Information | **Material** (2) | `missing_exclusions` | "All information disclosed" with no carve-outs. The playbook's baseline requires 4 standard exclusions (public, prior knowledge, independently developed, lawfully required disclosure). Without them, "Confidential Information" is unbounded. |
| c2 | Term | **Material** (2) | `term_too_long` | 5 year obligation + 5 year survival = 10 years total. The playbook's baseline is 2 year + 3 year survival. Plus, the contract's "in perpetuity" trade-secret expansion removes the baseline's "for so long as it remains a trade secret" hook. |
| c3 | Trade Secret Protection / Residual Knowledge | **Material** (2) | `missing_residual_knowledge_carveout` | No "unaided memory" carve-out. The Receiving Party's employees are bound by the full confidentiality obligation even for information that remains in their unaided memory — a real problem for engineers, salespeople, and other roles where general knowledge is the job. |
| c4 | Governing Law | **Material** (2) | `offshore_jurisdiction` | Cayman Islands law + courts. The playbook's baseline is Delaware / New Castle County. Cayman Islands is a meaningful surprise for a US/EU counterparty — the off-shore choice changes the dispute-resolution venue, not just the substantive law. |
| c5 | Remedies | **Unacceptable** (3) | `damages_cap_in_lieu_of_injunction` | USD 50,000 aggregate cap + explicit waiver of injunctive relief. The only "unacceptable" deviation (score 3) of the five — it removes the only remedy that actually deters a breach. Without an injunction, the Recipient can leak, pay the cap, and walk away. |

## How the asciinema uses these files

The Phase 6 asciinema card (`t_a8ee98b8`) records a 2-minute
screencast of the user flow:

1. `docker compose up -d` (assumes the dev stack is already up)
2. Open the frontend (live URL or `localhost:15173`)
3. Click **Upload** → select `demo/known-bad-nda.pdf`
4. Click **Triage** → see the deviation table populate with **5 rows** (c1, c2, c3, c4, c5)
5. Click **Approve** on all 5
6. Click **Generate Redline** → see the `.docx` download start
7. Open the downloaded `.docx` in Word / LibreOffice
8. Compare it against `demo/expected-redline.docx` — the
   strike/insert pairs should match (modulo timestamp + author)

## Reproducibility

The two build scripts are deterministic. Re-running either
produces a byte-identical artifact (modulo the `w:date`
attribute in the `.docx`, which carries the build timestamp):

```bash
# from the repo root
python scripts/build_demo_known_bad_nda.py
python scripts/build_demo_expected_redline.py
```

To re-record the `.docx`'s tracked-changes dates, re-run
`build_demo_expected_redline.py`. The deviation text and
author ("clausecraft") are stable.

## Why this isn't in `examples/`

The demo contract lives in `demo/` rather than
`examples/contracts/` because it's a demo artifact, not an
eval fixture:

- **Eval fixtures** (`examples/contracts/`) drive
  `evals/harness.py` — they measure whether the spotter's
  output matches a golden YAML. Each fixture has a single
  purpose (clean baseline, stress test, realism test,
  per-language variant).
- **Demo artifacts** (`demo/`) drive the asciinema. They
  have a different purpose: make a 2-minute screencast land
  the "wow" moment. The 5 deviations are stacked into a
  single contract so the demo's deviation table renders all
  5 rows at once (Phase 2 fixtures typically have 2-3
  deviations per contract; this one has 5 because the "wow"
  is the moment 5 rows light up).

Both have expected-deviation YAMLs in the same shape
(`expected_deviations: [clause_id, severity, category,
rationale, citation]`), but they're consumed by different
tools.

## Out of scope

- The asciinema `.cast` file itself — that's the
  `Asciinema / 2-min demo recording` card (`t_a8ee98b8`),
  parent-linked to this card + the deploy card. Athena owns
  the recording; this card ships the inputs.
- DE / multilingual variants of the demo contract — out of
  scope for v1 (the spec's "wow moment" is the EN NDA flow;
  DE is supported by the system, but the demo targets the
  EN track).
- A voice-over or video edit — asciinema is a terminal
  screencast, that's the format.
